# 随声字幕 · HearingAssist

**简体中文** | [English](README.en.md)

面向听障及重听人士的 Android 语音转字幕应用。将麦克风收到的对话转换为屏幕上的大字字幕，支持实时逐字预览、可选的说话人标注和环境音提醒。

**语音识别在手机本地运行；默认内置轻量模型，可离线使用。** 可选模型下载、版本检查和应用更新需要网络，不会因此上传录音或声纹。

[下载最新 APK](https://github.com/nakamisama/HearingAssist/releases/latest/download/app-release.apk) · [版本说明](https://github.com/nakamisama/HearingAssist/releases) · [构建记录](https://github.com/nakamisama/HearingAssist/actions)

## 快速开始

1. 下载 `app-release.apk` 并安装。若系统提示，请允许用于安装 APK 的应用“安装未知应用”。
2. 打开“随声字幕”，点击 **“点击开始”**，授予麦克风权限。
3. 首次启动会将内置小模型准备到本地缓存；完成后自动开始收听，无需下载大模型。
4. 点击右上角 **设置**，调整识别引擎、逐字预览、刷新间隔，或进入声纹管理。
5. 点击 **“点击停止”**结束。切到其他应用、回桌面或锁屏后也会自动停止；返回时需要手动开始。

### 设备要求

- Android 8.0（API 26）及以上；APK 包含 `arm64-v8a` 和 `armeabi-v7a` 原生库，不面向 x86 设备。
- 主要目标设备为 **荣耀 X50**。其他 Android 设备的麦克风表现、识别速度和内存占用需要实测。
- 基础字幕只需内置小模型；使用可选功能时需留出额外存储空间。

## 主要功能

| 功能 | 当前行为 |
| --- | --- |
| 实时模式（默认） | 内置轻量中文流式模型，边说边显示逐字预览；未安装大模型时由流式模型输出定稿。 |
| 精准模式（可选） | 使用另行下载的 SenseVoice 做分段识别。实际精度、标点效果和耗时取决于语音内容及设备。 |
| 简体中文 | 识别结果经 OpenCC 转为简体。 |
| 逐字预览设置 | 默认开启，默认刷新间隔 **200ms**；可选 100 / 200 / 300 / 500 / 1000ms。关闭后只看定稿。 |
| 字幕自动跟随 | 在文字排版完成后跟随最新内容，包括超过一屏的逐字预览；手动上滑回看会暂停，点击“回到最新”恢复。 |
| 声纹识别（默认关闭） | 朗读三句指定文字录入说话人，录入时选择字幕颜色；匹配成功后显示姓名和对应颜色。 |
| 环境音提醒（默认关闭） | 可选下载音频分类模型，在非语音时段尝试识别门铃、警报等声音，以文字和振动提示。 |
| 屏幕常亮 | 前台收听时保持亮屏，停止后恢复系统休眠行为；不会阻止手动锁屏。 |
| 后台自动停止 | App 不可见或锁屏后停止录音、取消待处理任务和下载，待在途推理结束后释放模型。回到前台不自动收听。 |
| 应用内更新 | 启动时检查版本，也可在设置中手动检查；确认后在 App 内下载，再交给系统安装器确认安装。 |

> 实时模式下，如果本地已经缓存 SenseVoice，当前实现也会加载它参与定稿。这会增加内存及计算开销，但不会仅因为使用实时模式就自动下载 SenseVoice。

## 模型与离线使用

| 模型 | 用途 | 获取方式 |
| --- | --- | --- |
| Silero VAD | 检测语音活动、切分语音 | 随 APK 内置 |
| Streaming Zipformer small CTC 中文 int8（2025-04-01 包） | 轻量流式识别 | 随 APK 内置 |
| SenseVoice int8（2025-09-09 包） | 可选分段识别与定稿 | 选择精准模式时按需下载 |
| 3D-Speaker CAM++ 中文 | 说话人声纹匹配 | 录入声纹或使用相关功能时按需准备 |
| Zipformer small audio tagging | 环境音分类 | 开启环境音功能时按需下载 |

- 模型保存在应用私有目录。**完整缓存可在覆盖安装更新后继续使用**；缓存可用且模型版本未变时不重复下载。
- 卸载应用、清除应用数据，或模型文件不完整，会影响缓存和声纹数据。
- 启动时先准备所需模型，再开启麦克风；界面显示准备进度。全部所需模型就绪后，识别不依赖网络。
- 包名中的日期是模型发布包的标识，不应直接当作训练完成日期。模型文件大小、APK 大小和运行内存是不同指标。

### 下载和网络规则

- **模型下载**：非计费 Wi-Fi / 以太网可直接下载所需模型；移动数据或计费网络需要两次确认，先建议切换 Wi-Fi，再确认可能产生流量费用。
- **APK 更新下载**：仅在 Wi-Fi 下进行；连接、源切换和校验阶段显示状态，传输时显示已下载大小和实际采样速率。服务器未提供总大小时不伪显示百分比。下载过程中网络变化或 App 切到后台会停止下载。重新回到 App 后由用户重试。
- **版本检查**：只是获取版本信息，不等于下载 APK，不限于 Wi-Fi。
- **默认更新渠道**：版本检查与 APK 下载统一优先尝试 `gh-proxy.com`，其次 `ghproxy.net`，失败后才回退 GitHub 官方直连；不需要配置开发电脑的7897代理。这些是第三方镜像，并非本项目自有的国内 CDN，手机端可用性不能保证。模型下载也保留镜像优先。
- 更新是**下载新 APK 后覆盖安装**，不是静默安装，也不是动态替换代码的热修复。安装器可能要求“安装未知应用”授权。

同包名、同签名且版本号允许时可覆盖安装并保留数据。早期使用不同签名的安装包，可能无法直接覆盖；卸载会清除应用数据。

## 声纹录入

1. 进入 **设置 → 管理声纹 → 添加说话人**。
2. 输入姓名，选择字幕颜色，并在安静环境下按提示朗读三句话。
3. 录入成功后回到设置，开启声纹识别。

建议先录入约四位常用说话人并做真机测试。短句、相似嗓音、多人重叠说话或与录入环境差异较大时，可能无法匹配或匹配错误。声纹标注不是身份认证，也不等同于多人同时说话的分离识别。

## 后台与数据处理

- 从主页进入声纹管理属于 **App 内部跳转**，不会单纯因为换页面而按后台退出处理。
- 录入时会暂停原字幕会话以避免抢占麦克风；若始终留在前台，录入结束或取消后可恢复原收听状态。切过后台则不自动恢复。
- 停止时先取消工作并停止收音，再等待正在进行的原生推理退出后释放模型，避免使用已释放的资源。
- 已定稿字幕保留在当前进程内存中，不是永久保存的对话记录；声纹特征和设置保存在应用私有目录。应用没有自动保存或上传原始录音的功能。
- Android 可能保留空闲进程和部分内存页，因此停止后不保证进程立即消失或内存显示归零。

技术细节见 [后台停止与资源释放](docs/BACKGROUND_STOP.md)。

## 已知限制与安全说明

- **不保证固定的出字延迟或识别准确率**。方言、距离、语速、噪声、手机温度和负载都可能影响结果。
- 当前以中文普通话为主。四川话、重庆话没有专用模型或准确率保证，不能将“自动识别”理解为支持所有方言。
- 环境音提醒可能漏报或误报，不能替代烟雾报警器、紧急警报或其他安全设备。
- **历史签名私钥曾进入公开 Git 历史，应视为已暴露。** 当前沿用签名是为兼容已有安装，不代表安全；后续需要单独规划密钥迁移与私密 CI 保管。只从可信渠道获取 APK。
- 模型缓存检查包含来源标识、文件长度及归档完整性，目前不等于可信发布方哈希认证。
- 云端测试和 lint 通过不等于荣耀 X50 或其他设备已经完成真机验收。

## 开发与构建

技术栈：**Kotlin、Android 原生界面、协程、AndroidX Lifecycle、sherpa-onnx、OpenCC**。

当前工作流使用 GitHub Actions，不要求在本机配置 Android 构建环境：

1. 检出代码，准备 JDK、AAR 和内置小模型。
2. 执行 `testReleaseUnitTest` 和 `lintRelease`。
3. 检查通过后执行 `assembleRelease`，上传 APK 与验证报告。
4. `main` / `master` 的 push 验证通过后发布可读版本，并更新 `updates/latest.json`。

### 版本命名与旧版升级

- 唯一待发布配置为 [release.properties](release.properties)，首个新格式名称为 **`bate1.0.1`**（保留项目采用的 `bate` 拼写）。用户提示、Release 标题和主 tag 使用此名称；设置中显示当前版本。
- Android `versionCode` 是独立递增的整数，仍用于更新比较及 APK 校验，不从名称字符串猜测。成功发布后推进下一补丁名称和整数编号；发布前失败不推进。
- 第一次迁移发布会为旧更新器保留一个 `build-N` 兼容入口，挂载同一真实签名 APK。旧 `version.json` 冻结在这个过渡版本；新客户端改读 `updates/latest.json`，后续只发布 `bate1.0.2` 等名称。
- 旧客户端升级前的提示可能仍是 build 编号；其 GitHub `/latest` 回退不能解析新名称，需要保留的旧清单或手动安装过渡版。
- 发布成功一部分但清单尚未提交时，不应覆盖已发布 tag 或虚改版本，应按发布记录人工核查恢复；完整成功后才推进配置。

当前配置也对 `fix/background-stop`、`fix/scroll-version`、`fix/update-download` 分支的 push 执行验证并上传 artifact，但不发布正式版。手动 `workflow_dispatch` 可构建指定分支，同样不会发布 Release。请以 [实际工作流](.github/workflows/build-apk.yml) 为准。

目前有 **38 项 JUnit 测试**，覆盖会话许可、取消与资源释放顺序、下载临时文件隔离、版本元数据和字幕跟随策略。这些测试使用模拟任务，并非真实麦克风或 JNI 性能测试；发布配置的 Python 测试另在 CI 中执行。
